# Система управления поставщиками

## Назначение проекта
Проект удобно управлять своими система поставок, поставщиками, договорами и товарами.

## Целевая аудитория
Целевой аудиторией проекта является малый и средний бизнес, у которого не так много ресурсов на разработку и поддержание собственных систем управления поставками.

## Веб-приложение · практики 9–11

SupplyManager ведёт поставщиков, каталог товаров, договоры и поставки с товарными позициями. Консольная версия запускается через `main.py` и по-прежнему работает с JSON. Веб-приложение работает с Django ORM и хранит данные в `db.sqlite3`.

### Запуск на Windows

Из корня проекта, в PowerShell, выполните команды. Для нового окружения сначала выполните `py -m venv venv`.

~~~powershell
.\venv\Scripts\python -m pip install -r requirements.txt
.\venv\Scripts\python manage.py migrate
.\venv\Scripts\python manage.py import_pr7
.\venv\Scripts\python manage.py createsuperuser
.\venv\Scripts\python manage.py runserver
~~~

Импорт выполняется один раз для пустой рабочей базы. В текущей рабочей копии он уже выполнен. Создайте свою учётную запись для входа в админку. Веб-интерфейс открывается по адресу http://127.0.0.1:8000/, административная панель — по /admin/.

### ПР9. Модели, миграции и перенос данных

Поставщику принадлежат товары и договоры. Поставка ссылается на поставщика и договор, а каждая её позиция связывает поставку с товаром и хранит количество. Ссылки на справочники защищены через PROTECT. Для удаления позиций вместе с поставкой используется CASCADE. Стоимость позиции вычисляется из количества и текущей цены товара, как в SQL-версии ПР7.

Команда `import_pr7` открывает `data/supply_manager.sqlite` только для чтения и переносит строки всех пяти таблиц в одной транзакции с сохранением ID. Чтобы указать другой исходный файл, передайте его путь после имени команды. Исходную SQL-схему и прежний импорт JSON можно изучить в каталогах `sql/` и `db/`.

| Страница | Что проверить |
| --- | --- |
| /suppliers/search/?q=770 | Поиск по фрагменту названия или ИНН |
| /suppliers/1/ | Поставщик и товары по обратной связи |
| /products/ | Сортировка по поставщику и товару, переход к карточке по ID и slug |
| /contracts/expiring/ | Активные договоры с окончанием в ближайшие 30 дней |
| /deliveries/ | Фильтры по периоду, поставщику, договору и статусу, сортировка, по 10 результатов на страницу |
| /deliveries/1/ | Позиции, количество, цена и сумма |
| /products/statistics/ | Количество товаров и поставок по статусам для каждого поставщика, суммарный остаток |

### ПР10. Административная панель и запросы

В панели зарегистрированы пять моделей. Откройте карточку поставщика или договора, чтобы увидеть связанные поставки. Позиции редактируются в карточке созданной поставки. Действие «Перевести на следующий этап поставки» последовательно проводит заказ через отправку, перевозку, приёмку и завершение. При переходе в статус «Принят» остатки увеличиваются в той же транзакции.

Для анализа запросов откройте панель SQL в Django Debug Toolbar на локальном сервере в режиме DEBUG. Без учёта инструментальных запросов список поставок без фильтра выполняет четыре запроса — подсчёт записей, выборку страницы с итогами и две выборки для полей формы. Карточка поставки выполняет два запроса независимо от числа позиций. Первый загружает поставку с поставщиком и договором, второй — позиции с товарами. Статистика использует условный Count, annotate и aggregate.

### ПР11. Формы и правила планирования

В разделе «Поставки» создайте заказ, выберите поставщика, активный договор, дату и хотя бы одну позицию. Товар и договор должны принадлежать выбранному поставщику. Количество должно быть положительным, дата — входить в срок договора. Для нового заказа можно выбрать сегодняшний или будущий день. При изменении старого заказа можно сохранить исходную дату.

Для демонстрации доступности ресурса договор резервируется под одну ожидающую приёмки поставку в день. Ограничение в базе распространяется на статусы «Создан», «Отправлен» и «В пути». Принятые, завершённые и отменённые поставки освобождают дату. Укажите одинаковые начало и конец периода в фильтре, чтобы увидеть свободные договоры на день. Карточка созданной поставки позволяет изменить заказ или отменить его с сохранением позиций и истории.

В карточке товара можно загрузить фотографию. Изображение проверяется Pillow и сохраняется в `media/products/`. Локальный сервер раздаёт загруженные файлы в режиме DEBUG.

### Проверка проекта

~~~powershell
.\venv\Scripts\python manage.py check
.\venv\Scripts\python manage.py makemigrations --check --dry-run
.\venv\Scripts\python manage.py test
.\venv\Scripts\python -m pytest -q
~~~

Django-тесты используют отдельную базу. Они проверяют создание, редактирование, ошибки формы, ограничения дат, отмену, приёмку, пагинацию, CSRF-защиту POST-запросов, загрузку фото и количество запросов. Pytest проверяет консольную предметную модель.
